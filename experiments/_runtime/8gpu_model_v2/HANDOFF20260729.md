## 2026-07-30 Update: pDockQ / DockQ Residue Reindex Fix Completed

This update supersedes the earlier "pDockQ / DockQ Bad Mapping Guard" behavior
described above.  The previous temporary behavior masked pDockQ supervision for
`7k3h_1` when raw PDB residue IDs reached DockQ scatter/gather.  That fallback
has now been replaced by a proper pDockQ-local residue-slot reindex.

### What Changed

- Added pDockQ-local DockQ residue slot generation in:
  `openfold3/core/loss/pdockq.py`

  New helper:

  ```python
  _dockq_residue_slots_from_batch(batch)
  ```

  It builds DockQ-private residue slots using only:

  - `token_mask`
  - `num_atoms_per_token`
  - `asym_id`
  - `residue_index`

  Effective tokens are:

  ```python
  token_mask.bool() & (num_atoms_per_token > 0) & (asym_id > 0)
  ```

  Slot semantics:

  - Traverse model tokens in order.
  - Maintain independent state per `asym_id`.
  - Reuse the current slot when the same chain sees the same adjacent
    `residue_index`.
  - Allocate the next 0-based slot when that chain advances to a new residue.
  - Keep invalid/padding tokens as slot `0`; they contribute no atoms.

- `per_candidate_complex_dockq()` now passes:

  ```python
  atomize(dockq_residue_slots)
  ```

  as `res_id_atomized`, instead of atomizing raw
  `batch["residue_index"]`.

- `batch["residue_index"]` is still left unchanged for model features,
  relative-position logic, audit/debugging, and any non-DockQ consumers.

- Removed the runner-level pDockQ mapping skip/mask fallback in:
  `openfold3/projects/of3_all_atom/runner.py`

  The string:

  ```text
  Skipping pDockQ target
  ```

  is no longer present in `runner.py`.  If DockQ mapping indices are still
  invalid after reindexing, the error now propagates as a real bug instead of
  silently dropping pDockQ supervision.

- Kept the lower-level bounds check in:
  `openfold3/core/utils/atomize_utils.py`

  This remains the protection against CUDA device-side scatter/gather asserts.

### Tests Updated

- `openfold3/tests/test_pdockq_loss.py`

  Added/updated coverage for:

  - DockQ receiving compact 0-based `res_id_atomized` slots.
  - Negative raw PDB residue IDs, e.g. `-4`.
  - Same-residue grouping across adjacent tokenized/atomized pieces.
  - Non-contiguous chain order such as `A, B, A`.
  - Padding / zero-atom tokens not advancing residue slots.

- `openfold3/tests/projects/of3_all_atom/physppi/model/test_pdockq_training_target.py`

  - Negative original residue IDs do not cause target masking.
  - DockQ mapping errors propagate instead of being swallowed.

  The existing out-of-range guard test remains in place.
