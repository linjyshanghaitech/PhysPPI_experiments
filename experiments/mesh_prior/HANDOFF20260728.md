# Mesh Prior 交接文档 — 2026-07-28

## 我们在做什么

**目标**：替换 PhysPPI 训练中旧的 surface 特征提取方式（`build_surface_features`，
CA center + KNN 128 最近邻），改为 **KDTree 最近重原子映射**（每个 mesh 顶点找最近
重原子，归属于该原子所在的残基，单点单残基）。

**收益**：
- 语义正确：每个 surface 顶点物理上属于唯一残基，不再被多个残基共享
- 可预计算：映射关系固定，离线生成 `.pt` 后训练时直接 `torch.load()`，跳过 KNN 计算
- K 可调：K=64 覆盖 99.7% 残基（vs 旧方法固定 K=128，50% 内存减小）

## 踩过的坑——绝对不要再踩

### 1. 坐标系不一致（最坑）

mesh 顶点在 PKL 里是 **monomer-local 坐标系**（因为 MSMS 从 `bb_input/{case_id}_{chain_id}.pdb` 生成）。
KDTree 必须用 **同一个坐标系** 的 PDB 建树 → 必须用 `bb_input/` PDB，**不能用 `gt/` PDB**（GT PDB 是 complex 坐标系）。

第一次实现用了 GT PDB 导致坐标完全对不上，被用户发现后才改过来。

### 2. seq_cache.N ≠ GT PDB 残基数

`seq_cache.pkl` 的 `full_seq_1aa` 长度可能大于 GT PDB 实际残基数（unresolved 区域）。
`.pt` 的 `N` 必须等于 `seq_cache` 的 N，不能等于 GT PDB 的 N。
对于 GT PDB 中不存在的残基，`resseq` 设为 -1，data 行全零。

第一次生成 `.pt` 时 resseq list 长度 ≠ data.shape[0]，被 gap 样本 `8iru_1`（chain A 356 sequences vs 231 PDB residues）暴露后修复。

### 3. v3 bb_input 只有 backbone 原子

`bb_input/` PDB 只含 N, CA, C, O，没有侧链原子，没有 CB。
旧方案 `_surface_token_frames()` 用 CB 做 center → 退化为 CA（100% 走 CA 分支）。
我们的 KDTree 也只能用 backbone 原子。

这个在 v4 数据到来后会自然解决（v4 bb_input 是全链全原子）。

### 4. v4 不需要重新跑 KDTree

v4 的 PKL 里已经有 `{case_id}_point_to_residue` key：
```python
pkl = pickle.load(path)
mapping = pkl[f"{case_id}_point_to_residue"]  # {chain_id: [res_idx_per_vertex, ...]}
```
这是 `mesh_prior.py:compute_point_to_residue()` 生成的，和我们 `generate_mesh_tensors.py`
的 KDTree 逻辑完全等价。切到 v4 后直接读这个 key，不要再跑 KDTree。

### 5. .pt 路径推导依赖目录结构

`_runtime.py` 中的 helper 通过 `prior_pkl` 路径反推 chunk 名和 dataset root：
```
prior_pkl = .../training/AFDB-10k-1/chunk/chunk0008/prior_pkl/AF-xxx.pkl
→ chunk_name = prior_pkl.parent.parent.name = "chunk0008"
→ dataset_root = prior_pkl.parent.parent.parent.parent = .../training/
→ mesh_pt = dataset_root / "precomputed_mesh/cli_v3/AFDB-10k-1/chunk0008/AF-xxx_mesh.pt"
```
如果目录结构变了（比如更换数据集路径或 chunk 组织方式），这个推导会失效。
`_MESH_PT_DATASET_MAP` 映射 `self.name` → 数据集目录名，新增数据集时需更新。

### 6. _runtime.py 语法验证失败不等于代码有问题

验证环境缺 `pydantic` 等依赖，`import _runtime` 会报 `ModuleNotFoundError`。
用 `py_compile.compile(path, doraise=True)` 验证语法，返回 `Syntax OK` 即可。

### 7. 旧方法的分析要讲清楚

用户多次纠正对旧方法 `build_surface_features` 的描述。写文档时必须明确：
- center = CB（如有且非 GLY）else CA（v3 100% 走 CA）
- KNN 是按 center 到所有 mesh 点的欧式距离排序取 128
- basis 用 N/CA/C 三原子构建
- 这是残基级别的独立 KNN → 边界点可能被多个残基共享

### 8. bb_input / seq_cache 残基不对齐（最隐蔽的坑）

**根因**：Q-BioLiP 某些晶体结构在 N 端有表达标签（如 `2pgc_1` chain A 的 GLY resseq=0），
bb_input PDB 包含这些残基，但 `seq_cache.pkl` 的 `full_seq_3aa` 不包含。

**症状**：`len(bb_input_residues) > len(seq_cache)` → 按位置直接映射 → 全链偏移 1 位。
`data[0]` 被 expression tag 占据，`data[-1]` 的 LEU 因越界丢失。

**修复**：`2026-07-28 最终版` 改为 greedy sequence-name matching：
```python
# 对 seq_cache 每个位置的残基名，在 bb_input 中顺序匹配同名的残基
# 匹配失败的 bb_input 残基（terminal artifact）→ 跳过
# 匹配不到的 seq_cache 残基（unresolved）→ resseq=-1
bb_idx = 0
for seq_idx, seq_res in enumerate(seq_3aa):
    while bb_idx < len(bb_order):
        bb_resseq, bb_res = bb_order[bb_idx]
        bb_idx += 1
        if bb_res == seq_res:
            resseq_to_seq_idx[bb_resseq] = seq_idx
            break
```
这个修复同时处理了 N-terminal artifacts 和 unresolved residues 两种情况。
