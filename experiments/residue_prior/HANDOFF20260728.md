# Residue Prior 交接文档 — 2026-07-28

## 我们在做什么

**目标**：把 `prior_pkl` 里的 residue-level prior（dmap / interactions / OPM）抽出来，独立存成 `.pt`，
让训练时跳过 pickle 反序列化整个 `prior_pkl`，按需 `torch.load` 各自独立的 `.pt`。

PhysPPI 有 4 个 optional prior，其中 3 个是 residue-level 的：

| prior | `.pt` 文件名 | 来源 |
|-------|-------------|------|
| (Non-) Interface residues | `{case_id}_interface_residues.pt` | `prior_pkl` 的 `.dmap` |
| Interaction pairs | `{case_id}_interaction_pairs.pt` | `prior_pkl` 的 `.interactions` |
| Membrane relative location | `{case_id}_membrane_relative_location.pt` | `prior_pkl` 的 `.opm` |

**收益**：
- 三个 prior 独立可配：哪个 `.pt` 存在就 load 哪个，不存在静默回退旧逻辑
- `torch.load` 比 `pickle.load` 快，且不用反序列化 mesh 数据
- 文件小（~20-100 KB per sample），总计 ~6.9 GB（vs mesh 的 ~61 GB）
- 与 mesh `.pt` 存在同一目录树下

### 3. `.pt` 格式

**`{case_id}_interface_residues.pt`** — dmap（CA-CA ≤ 18Å）：

```python
{
    "dmap": {
        "A|B": torch.tensor([[r_a, r_b, dist], ...], dtype=torch.float32),
        # r_a, r_b 是 PDB resseq，dist 保留用于 cutoff 增强
    },
}
```

**`{case_id}_interaction_pairs.pt`** — 5 种 PLIP 相互作用：

```python
{
    "interactions": {
        "A|B": {
            "pairs": torch.tensor([[r_a, r_b, type_id], ...], dtype=torch.int32),
            # type_id: 0=hbond  1=saltbridge  2=hydrophobic  3=pistacking  4=pication
            "atom_1": [("ND2",), ("CB", "CG"), ...],
            "atom_2": [("OE1", "OE2"), ("CD1",), ...],
        },
    },
}
```

- 不存 distance，atom names 保留用于 loss 时从 GT PDB 实时算质心距离
- 只有 5 种（去掉了 waterbridge 和 halogen）

**`{case_id}_membrane_relative_location.pt`** — OPM 膜平面：

```python
{
    "res_loc": {
        "A": torch.tensor([[1, 22, 1], [23, 54, 0], ...], dtype=torch.int32),
        # [start_resseq, end_resseq, side]，side: 1/0/-1
    },
    "plane": {
        "normal": torch.tensor([nx, ny, nz], dtype=torch.float32),
        "centroid": torch.tensor([cx, cy, cz], dtype=torch.float32),
        "thicken": 26.8,
    },
}
```

### 4. Adapter 接口

`residue_adapter.py` 提供 4 个函数，完全对上旧 `_builders.py` 的返回格式：

```python
from experiments.residue_prior.residue_adapter import (
    build_contact_from_precomputed,          # ↔ build_contact_features()
    build_interaction_from_precomputed,      # ↔ build_interaction_features()
    build_tm_from_precomputed,               # ↔ build_tm_features()
    build_membrane_target_from_precomputed,  # ↔ build_membrane_target()
)
```

- contact: `torch.load(.pt)` → `token_index.get((chain, resseq))` → `[N,N]` bool mask
- interaction: 同上 + atom names → GT PDB centroid distance (loss 用)
- tm: interval → per-residue `[N]` bool mask (只取 side==0)
- membrane: plane normal + centroid → `{valid, normal, point}`

## 踩过的坑——绝对不要再踩

### 1. ProcessPoolExecutor 必须预先创建输出目录

`output_dir.mkdir(parents=True, exist_ok=True)` 在 worker 子进程中有时不生效
（可能是 NFS/文件系统并发问题）。**必须先在主进程创建所有 chunk 输出目录，再启动 worker**。

```bash
for chunk in $(ls training/{dataset}/chunk/); do
    mkdir -p precomputed_mesh/cli_v3/{dataset}/${chunk}
done
```

### 2. AFDB 的 interactions 不是空的

第一次抽样检查 chunk0008 没有 interactions，结论是"AFDB 全空"——**错误的**。
完整扫描发现 AFDB 有 ~65% (6,564/10,000) 样本有 interactions。
永远不要用单 chunk 的结论推断全数据集。

### 3. interactions 只保留 5 种类型

旧代码和 PLIP 支持 7 种（含 waterbridge 和 halogen），但这两类在训练中未被使用。
生成的 `.pt` 只保留了 5 种（hbond / saltbridge / hydrophobic / pistacking / pication）。
如果以后要加回来，需要重新生成 `_interaction_pairs.pt`。

### 4. 三个 .pt 必须独立，不能合并

最初设计是把 dmap + interactions 合并成一个 `_residue.pt`，后来拆成独立文件。
原因：AFDB 有 35% 没有 interactions，Q-BioLiP 有 24% 没有 membrane。
合并会让训练时 load 一个"半空"的 `.pt`，浪费 I/O。

### 5. PDB resseq 是唯一正确的 key，不需要 seq_cache 对齐

mesh_prior 需要在 seq_cache 和 PDB resseq 之间做复杂的 greedy sequence-name matching
（见 mesh_prior HANDOFF 的坑 #8）。residue prior **不需要**这层对齐——
dmap/interactions/OPM 都直接用 PDB resseq，adapter 端 `token_index.get((chain, resseq))`
一行就能处理 crop。绝对不要引入 seq_cache 依赖。

### 6. interactions 的 atom names 不可丢弃

虽然不用 interactions 的 distance 做模型输入，但 atom names 是 loss 计算必需的——
`_build_pair_interaction_auxiliary` 需要从 GT PDB 原子坐标实时算质心距离。
生成 `.pt` 时必须保留 `atom_1` 和 `atom_2`。

### 7. 生成命令的 `--output-dir` 路径

residue `.pt` 放在 mesh `.pt` 的同级目录：

```
/101045/jinyu/PPI/Prior_out/precomputed_mesh/cli_v3/{dataset}/{chunk}/
```

**不要**创建新的 `precomputed_residue/` 目录——`_runtime.py` 的路径推导基于 mesh 目录结构。

### 8. 单个 `.pt` 大小估算

- `_interface_residues.pt`: 几千对 × 12 bytes + tensor overhead ≈ 20-100 KB
- `_interaction_pairs.pt`: 几十到几百条 × (12 + strings) ≈ 5-20 KB
- `_membrane_relative_location.pt`: 几个 intervals + plane ≈ 2-5 KB
- 总计每个 sample ~30-120 KB，比 mesh .pt (~850 KB) 小一个数量级

### 9. `torch.load` 需要 `weights_only=False`

因为 `.pt` 里有 Python tuple（atom names），`weights_only=True` 会报错。
adapter 里统一用 `torch.load(path, map_location="cpu", weights_only=False)`。
